# Students API

REST API to manage students (CRUD and search), built with NestJS and deployed to AWS with the Serverless Framework. Data is stored in DynamoDB and the endpoints are protected with an API key.

> The API key is not in this repository. It is delivered separately, together with the demo URL.

With npm run deploy you can get the url of the project, configuring the AIM user.

# How I solved it

## Technologies

- **TypeScript** on **Node.js**
- **NestJS 11**: API framework
- **Serverless Framework v4**: infrastructure definition and deployment
- **AWS Lambda**: runs the API (`nodejs22.x`)
- **AWS API Gateway (REST)**: public URL, routes, API key, usage plan and CORS
- **AWS DynamoDB**: NoSQL database, single table, pay-per-request
- **AWS IAM** and **CloudFormation**: permissions and resources, generated by Serverless
- **Swagger / OpenAPI**: interactive documentation
- **Jest**: unit tests

## Concepts applied

**Architecture**
- Layers: controller → service → repository
- Nest modules, one per feature
- Dependency injection and loose coupling
- Repository pattern to isolate DynamoDB access
- DTOs to define and validate input data
- Configuration through environment variables

**API**
- REST with GET, POST, PATCH and DELETE
- Global request validation, rejecting undeclared fields
- Centralized error handling with a uniform format
- Server-generated UUID identifiers
- Text search that ignores case and accents
- CORS configured
- Swagger documentation

**Security**
- Private endpoints with an API key and a usage plan (quota and rate limit)
- No credentials in the code: `.env` kept out of git and a least-privilege IAM role

**DynamoDB**
- Single table with partition key `alumnoId`
- Conditional writes (do not overwrite on create, do not create on update)
- Partial updates with expressions and placeholders
- Scan pagination

**Serverless**
- Infrastructure as code, declarative
- Express-to-Lambda adapter
- Cold starts and server reuse between invocations

## Requirements

- Node.js `<NODE_VERSION>` or later
- An AWS account with credentials configured on your machine (`aws configure`)
- A Serverless Framework account (`serverless login`), required by v4

## Running locally

```bash
npm install
cp .env.example .env
npm run start:dev
```

The `.env` file defines the table name:

```
TABLE_NAME=alumnos-api-dev-alumnos
```

Locally, the API uses your AWS credentials and connects to the real DynamoDB table, so the table must exist (it is created by the first deployment). The API is available at `http://localhost:3000` and the documentation at `http://localhost:3000/docs`.

## Deployment

```bash
npm run deploy
npx serverless info --stage dev
```

The first command builds with `nest build` and deploys to the `dev` stage. The second one shows the base URL and the API key.

To remove everything from AWS (including the table and its data):

```bash
npm run remove
```

## Authentication

All endpoints, except the documentation, require the `x-api-key` header:

```
x-api-key: <YOUR_API_KEY>
```

Without the key, API Gateway responds with `403 Forbidden` in its own format, before the request reaches the application.

## Endpoints

Routes are served under the stage: `<YOUR_URL>/alumnos`.

| Method | Path | Description | API key | Response |
| --- | --- | --- | --- | --- |
| POST | `/alumnos` | Creates a student | Yes | `201` |
| GET | `/alumnos` | Lists students | Yes | `200` |
| GET | `/alumnos?q=text` | Searches by first name, last name or email | Yes | `200` |
| GET | `/alumnos/{id}` | Gets one student | Yes | `200` / `404` |
| PATCH | `/alumnos/{id}` | Updates fields of a student | Yes | `200` / `404` |
| DELETE | `/alumnos/{id}` | Deletes a student | Yes | `204` / `404` |
| GET | `/health` | Service status | Yes | `200` |
| GET | `/docs` | Swagger UI | No | `200` |
| GET | `/docs/json` | OpenAPI specification | No | `200` |

### Model

| Field | Type | Rules |
| --- | --- | --- |
| `alumnoId` | UUID | Generated by the server; not sent by the client |
| `nombre` | text | Required, max 100 characters (first name) |
| `apellido` | text | Required, max 100 characters (last name) |
| `email` | text | Required, valid email format, max 150 characters |
